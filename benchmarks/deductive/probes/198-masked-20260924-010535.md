Note that the Lean hypothesis allows w = x. So it also forbids 2a = b + c with {a, a} ≠ {b, c}. That is the standard Sidon condition with repeated summands included.

**2. Proof strategy (my own proposal, not recalled from a source)**

A greedy / diagonal construction should work, and I expect this version to be easy.

1. Enumerate all pairs (c, e) with e > 0 as a sequence (cₙ, eₙ). There are countably many.
2. Build a finite Sidon set Bₙ inductively. At stage n, choose an element aₙ = cₙ + s·eₙ, taking s large.
3. The new element must avoid finitely many forbidden values determined by Bₙ₋₁:
   - a = b + c − d,
   - 2a = b + c, i.e. a = (b + c)/2,
   - a = 2b − c,
   - a ∈ Bₙ₋₁,

   where b, c, d range over Bₙ₋₁.
4. Taking aₙ larger than, say, 2·max Bₙ₋₁ automatically avoids all of these. Then Bₙ = Bₙ₋₁ ∪ {aₙ} is still Sidon.
5. Set B = ⋃ Bₙ. The Sidon property is finitary, so it passes to the union. Each progression is hit at its own stage.

In Lean, the cleanest route is probably to define aₙ recursively, for example aₙ = cₙ + s·eₙ with s = 2·aₙ₋₁ + 1 (or any explicit bound making aₙ > 2·aₙ₋₁). From aₙ > 2·aₙ₋₁ one gets a rapidly increasing sequence, and the Sidon property follows from a lacunarity argument. The pairing of indices can come from `Nat.unpair`.
